### 1️⃣ **create_lot.php** (Блок 2 - Поля временных меток)

**Проблема:** Форма создания лота не содержит полей для сохранения временных меток лота  
**Решение:** Добавлены поля для управления временем начала, длительностью и максимальной продолжительностью

**Что добавлено:**
- Поле `start_at` (datetime-local) - отложенный старт торгов
- Поле `time_before_start` (число) - минуты до начала (для UI "Начинается через...")
- Поле `max_duration` (число) - максимальная продолжительность торгов (жёсткое закрытие)
- Поле `duration` (число) - обновлено, стандартная длительность

**Структура добавленного HTML:**
```html
<div class="time-section">
    <h4>⏰ ПАРАМЕТРЫ ВРЕМЕНИ ТОРГОВ</h4>
    <div class="field-group">
        <label>Начало торгов (опционально)</label>
        <input type="datetime-local" name="start_at" ...>
    </div>
    <div class="grid-2">
        <input type="number" name="duration" ...>
        <input type="number" name="time_before_start" ...>
    </div>
    ...
</div>
```

**Применение:**
```bash
cp patches/create_lot.php ./create_lot.php
```

**Проверка:** После применения откройте `/create_lot.php` и проверьте наличие новых полей в форме

### 2️⃣ **reestr.php** (Блок 3 - Автообновление статусов)

**Проблема:** При загрузке реестра лоты не меняют статус с `active` на `finished` после истечения времени  
**Решение:** Добавлена логика автоматического обновления статусов при загрузке страницы

**Что добавлено (после `date_default_timezone_set`):**
```php
// Завершаем лоты, время которых истекло
UPDATE lots SET auction_status = 'finished' 
WHERE auction_status = 'active' 
AND end_time IS NOT NULL 
AND end_time <= NOW()

// Помечаем как 'single' лоты с единственной ставкой
UPDATE lots SET auction_status = 'single' 
WHERE ...
```

**Результат:** При каждой загрузке `/reestr.php` автоматически проверяются и обновляются статусы лотов

**Применение:**
```bash
cp patches/reestr.php ./reestr.php
```

**Проверка:** Создайте лот с конечным временем в прошлом, затем откройте `/reestr.php` - статус должен измениться на "Завершён"

### 3️⃣ **profile.php** (Блок 4 - Кнопка повышения статуса)

- Функции JavaScript: `openUpgradeModal()`, `upgradeQR()`, `upgradeReceipt()`
- Переменные: `$upgrade_cost`, `$can_upgrade`
- Условное отображение (скрыто для уже ответственных пользователей)

**Структура:**
```html
<button class="btn btn-success upgrade-btn" onclick="openUpgradeModal()">

</button>
```

**Применение:**
```bash

```

**Проверка:** Откройте `/profile.php` как "Уважаемый" - должна появиться кнопка "⭐ Повысить статус"

### Блок 9 - CSS выводится как текст

**🔍 Найденная проблема:**  
На главной странице https://forsage.ct.ws CSS медиа-запросы выводятся как обычный текст между навигацией и контентом.

```
ГЛАВНАЯ  ТОРГИ  КОМИССИОННАЯ  ВХОД
/* ═════════════════════════════════════════════════════ */
/* МОБИЛЬНАЯ АДАПТИВНОСТЬ */
/* ═════════════════════════════════════════════════════ */
@media (max-width: 768px) { ... }
```

**📍 Местоположение:** 
- HTML позиция: После `</header>`, до основного контента
- Видимо между heading и main section

**❓ Вероятные причины:**
1. Незакрытый `<style>` тег в header.php (хотя header.php выглядит OK)
2. CSS-код случайно попал в HTML (в тег script или просто в body)
3. Ошибка в index.php - может быть неправильное включение CSS

**⚠️ Требуется:**
- Проверить HTML структуру между `</header>` и `<main>`
- Убедиться в наличии парных `<style>` и `</style>` тегов
- Проверить нет ли CSS внутри `<script>` тегов
